# Мок Backend и заглушка ML-сервиса

Мок Backend шлёт в ML-сервис запросы по [API.md](../API.md), как это будет делать настоящий Backend,
и проверяет ответы на соответствие контракту. Компании и заявки берутся из `data/applications.csv`.

| Файл | Что делает |
|---|---|
| `mock_backend.py` | шлёт запросы в `/offers`, `/approval`, `/alternative`, проверяет контракт, считает метрики |
| `ml_stub.py` | заглушка ML-сервиса: настоящая валидация (422), константные прогнозы |
| `contract.py` | поля `Company`, каталог продуктов (раздел 5), `validate_company` / `validate_offer` |
| `data.py` | строка CSV → `Company` / `Offer`; разбиение train/test по ИНН |

Зависимости: только numpy и pandas, HTTP на стандартной библиотеке.

## Запуск

Из папки `ML_Part`:

```bash
python mock/ml_stub.py --port 8000                                  # или свой сервис
python mock/mock_backend.py --url http://localhost:8000 --n 300     # во втором терминале
```

| Параметр | По умолчанию | Описание |
|---|---|---|
| `--url` | `http://localhost:8000` | адрес ML-сервиса |
| `--scenario` | `all` | `offers`, `approval`, `alternative`, `errors` или `all` |
| `--n` | 300 | запросов на сценарий (`errors` — фиксированный набор из 27) |
| `--split` | `test` | какие компании брать: `test`, `train`, `all` |
| `--gamma` | случайно 0.5 / 0.7 / 0.9 | порог для `/alternative` |
| `--workers` | 8 | параллельных запросов |
| `--dump` | — | JSONL со всеми запросами и ответами |
| `--show` | 5 | сколько нарушений печатать на сценарий |

Код выхода 1, если хоть один ответ нарушил контракт: можно использовать в CI.

## Что проверяется

| Сценарий | Контракт | Метрики |
|---|---|---|
| `offers` | 10 предложений, по одному на продукт; по убыванию `oftenhood`; каждое `Offer` допустимо для компании | top-1 и recall@3: попадание в продукты, на которые компания реально подавала заявки |
| `approval` | `approval_probability` в 0…1 | AUC, logloss, Brier по колонке `approved`; средний прогноз против факта |
| `alternative` | `approval_probability > gamma`; продукт тот же; залог не больше исходного; если исходное проходит порог, возвращается оно с `likelyhood` 1; если `offer` = null, остальные поля null; вероятности совпадают с `/approval` для того же предложения | сколько проходят порог сразу; скольким найдена альтернатива; средний `likelyhood` |
| `errors` | 23 неверных запроса → 422 с `{"error": {"code": "VALIDATION_ERROR", ...}}`; 4 контрольных → 200 | — |

## Разбиение train/test

5% компаний попадают в тест по хэшу ИНН (`data.is_test`). Решение не зависит от seed и порядка строк.
По умолчанию мок шлёт только тестовые компании, поэтому при обучении их нужно исключить:

```python
import sys; sys.path.insert(0, "mock")
from data import load_applications, test_mask

df = load_applications()
train = df[~test_mask(df)]
```

## Точка отсчёта: заглушка

Константные прогнозы заглушки дают метрики, которые модели должны превзойти
(данные v1.4, `--n 300`, `--seed 0`, тестовая часть):

| Ручка | Заглушка |
|---|---|
| `/offers` | top-1 40.3%, recall@3 57.3% (сортировка по базовым весам спроса) |
| `/approval` | AUC 0.608 (доля одобрения продукта, без учёта компании) |
| `/alternative` | альтернатива не находится никогда |
