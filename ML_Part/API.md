# API: подбор кредитных продуктов для МСБ

Контракты между сервисами. По ним каждый может разрабатывать свою часть независимо.

```
Фронт ──► Backend ──┬──► ML: модель 1 (контейнер model1)   POST /offers
                    └──► ML: модель 2 (контейнер model2)   POST /approval, POST /alternative
```

| Сервис | Что делает |
|---|---|
| Фронт | ввод ИНН, выбор продукта, ввод параметров; вызывает Backend |
| Backend | находит данные компании по ИНН, собирает объект `Company` и передаёт запрос в ML |
| ML: модель 1 | подбирает продукты и условия (`/offers`) |
| ML: модель 2 | считает шанс одобрения и ищет похожее предложение с высоким шансом (`/approval`, `/alternative`) |

ML-сервисы ничего не запрашивают сами: всё нужное приходит в запросе. Это два отдельных контейнера
с двумя адресами; у Backend — два адреса в настройках. Локально: модель 1 — `localhost:8000`,
модель 2 — `localhost:8001`.

**Формальные признаки отказа проверяет ML (модель 2)** — список в [model2/REJECT_RULES.md](model2/REJECT_RULES.md):
заблокированы счета, банкротство, возраст, условия `GOV_1764` и `FACTORING`, сумма больше лимита (выручка +
ликвидная стоимость залога), платежи за год больше выручки.
Если заявка не проходит — `approval_probability` = 0.

**Соглашения:** JSON; суммы — целые рубли; ставки — % годовых; сроки — месяцы; флаги — `true`/`false`;
нет данных — `null`.

## 1. Данные: таблица заявок

Мок-данные — `data/applications.csv`: одна строка = одна заявка компании на один продукт, 30 колонок,
за 2 года (2024-10 — 2026-09), по дате. У компании может быть несколько заявок, в том числе повторные на тот
же продукт после отказа (с меньшей суммой, залогом или другим сроком). Признаки компании в заявке — на месяц
её подачи. Помесячная история признаков всех компаний — `data/company_snapshots.csv.gz` (колонка `month`,
`inn` и 19 колонок компании).
Пустая ячейка = нет данных, флаги — 0/1.

```python
pd.read_csv("data/applications.csv", dtype={"inn": str})   # иначе ИНН станет числом
```

Таблица компаний для мок-данных Backend (поиск по ИНН) — последний месяц из `company_snapshots.csv.gz`:
`month == "2026-09-01"`, колонки `inn` + 19 колонок компании.

## 2. Объекты

### `Company` — компания

ИНН и 19 колонок компании из раздела 1, с теми же именами и типами. Флаги — `true`/`false`.
Все поля обязательны (поле с «нет данных» передаётся как `null`).

```json
{
  "inn": "7701234560",
  "legal_form": "LLC",
  "company_age_months": 103,
  "okved_section": "G",
  "msp_category": "micro",
  "revenue_last_year": 48200000,
  "revenue_growth_yoy": 0.161,
  "net_margin": 0.027,
  "equity_ratio": 0.361,
  "current_ratio": 0.993,
  "debt_to_revenue": 0.052,
  "taxes_paid_last_year": 1284500,
  "tax_arrears_amount": 0,
  "accounts_blocked_flag": false,
  "registry_risk_flag": false,
  "bankruptcy_flag": false,
  "fssp_open_amount": 48000,
  "arbitr_defendant_amount_12m": 870000,
  "bki_total_debt": 2070000,
  "bki_max_dpd_12m": 12
}
```

### `Offer` — предложение

7 колонок предложения из раздела 1. Допустимые значения для каждого продукта — в разделе 5.

```json
{
  "product_type": "WORKING_CAPITAL",
  "amount": 5000000,
  "term_months": 24,
  "rate": 20.0,
  "collateral_value": 6000000,
  "collateral_type": "REAL_ESTATE",
  "collateral_subtype": "WAREHOUSE"
}
```

Вид залога: без залога (`collateral_value` = 0) — оба поля `null`; с залогом — оба обязательны,
частный вид должен относиться к общему (раздел 6). `/offers` вид залога не предлагает: в его ответе
`Offer` без этих двух полей, вид выбирает клиент.

## 3. Ошибки (общий формат)

```json
{ "error": { "code": "VALIDATION_ERROR", "message": "term_months=7 недопустим для WORKING_CAPITAL" } }
```

| HTTP | `code` | Когда |
|---|---|---|
| 422 | `VALIDATION_ERROR` | в `Company` не хватает полей или значение неверного типа; параметры `Offer` вне допустимых значений (раздел 5) |
| 500 | `INTERNAL_ERROR` | внутренняя ошибка |

## 4. ML-сервис

Во всех запросах передаётся объект компании `company`. ML-сервис ничего не запрашивает сам.

С точки зрения ML-сервиса все поля `Company` всегда доступны: согласие на запрос в БКИ клиент даёт при
первом входе в кабинет, и Backend собирает все данные до любого вызова. `null` в поле значит, что
данных нет у самого источника (например, нет кредитной истории или нет отчётности), а не что их не
запросили.

### 4.1. `POST /offers` — какие продукты предложить

По одному предложению на каждый из 10 продуктов, отсортированы по `oftenhood`.

**Запрос:**

```json
{
  "company": { "inn": "7701234560", "legal_form": "LLC", "...": "все поля Company" }
}
```

**Ответ `200`:**

```json
{
  "offers": [
    {
      "offer": { "product_type": "OVERDRAFT", "amount": 1800000, "term_months": 12,
                 "rate": 21.5, "collateral_value": 0 },
      "oftenhood": 0.41
    },
    {
      "offer": { "product_type": "WORKING_CAPITAL", "amount": 7000000, "term_months": 24,
                 "rate": 20.0, "collateral_value": 0 },
      "oftenhood": 0.33
    }
  ]
}
```

| Поле | Тип | Описание |
|---|---|---|
| `offers` | array, 10 элементов | по одному на продукт, по убыванию `oftenhood` |
| `offers[].offer` | `Offer` без вида залога | предложение по продукту |
| `offers[].oftenhood` | float, 0…1 | насколько часто похожие компании хотят этот продукт |

### 4.2. `POST /approval` — шанс одобрения

**Запрос:**

```json
{
  "company": { "inn": "7701234560", "legal_form": "LLC", "...": "все поля Company" },
  "offer": { "product_type": "WORKING_CAPITAL", "amount": 5000000, "term_months": 24,
             "rate": 20.0, "collateral_value": 6000000,
             "collateral_type": "REAL_ESTATE", "collateral_subtype": "WAREHOUSE" }
}
```

**Ответ `200`:**

```json
{ "approval_probability": 0.71 }
```

| Поле | Тип | Описание |
|---|---|---|
| `approval_probability` | float, 0…1 | шанс одобрения |

### 4.3. `POST /alternative` — похожее предложение с высоким шансом одобрения

Возвращает одно предложение, максимально похожее на исходное, у которого шанс одобрения больше `gamma`.
Если исходное само проходит порог — возвращается оно. Продукт (`product_type`) тот же, что в исходном;
залог в ответе не больше исходного и того же вида (или без залога).

**Запрос:**

```json
{
  "company": { "inn": "7701234560", "legal_form": "LLC", "...": "все поля Company" },
  "offer": { "product_type": "INVESTMENT", "amount": 30000000, "term_months": 36,
             "rate": 16.0, "collateral_value": 0, "collateral_type": null, "collateral_subtype": null },
  "gamma": 0.9
}
```

| Поле | Тип | Описание |
|---|---|---|
| `company` | `Company` | компания |
| `offer` | `Offer` | исходное предложение |
| `gamma` | float, 0…1 | минимальный шанс одобрения |

**Ответ `200`:**

```json
{
  "source_approval_probability": 0.47,
  "offer": { "product_type": "INVESTMENT", "amount": 18000000, "term_months": 84,
             "rate": 19.5, "collateral_value": 0, "collateral_type": null, "collateral_subtype": null },
  "likelyhood": 0.74,
  "approval_probability": 0.91
}
```

| Поле | Тип | Описание |
|---|---|---|
| `source_approval_probability` | float | шанс одобрения исходного предложения |
| `offer` | `Offer` или `null` | найденное предложение; `null` — подходящего нет (это не ошибка) |
| `likelyhood` | float, 0…1, или `null` | похожесть на исходное; 1 — то же самое |
| `approval_probability` | float или `null` | шанс одобрения найденного |

## 5. Продукты

Допустимые значения для `Offer`. Значения вне таблицы — `422`.

| `product_type` | Название | `amount`, ₽ | `term_months` | `rate`, % | `collateral_value` |
|---|---|---|---|---|---|
| `OVERDRAFT` | Овердрафт | 100 000…50 000 000 | 3, 6, 12 | 12.9…34.4 | всегда 0 |
| `BUSINESS_CARD` | Кредитная бизнес-карта | 50 000…5 000 000 | 12, 24, 36 | 15.0…40.0 | всегда 0 |
| `EXPRESS_UNSECURED` | Экспресс-кредит без залога | 300 000…15 000 000 | 6, 12, 24, 36 | 14.4…38.4 | всегда 0 |
| `WORKING_CAPITAL` | Оборотный кредит | 500 000…100 000 000 | 6, 12, 18, 24, 36 | 12.0…32.0 | ≥ 0 |
| `CREDIT_LINE_REV` | Возобновляемая кредитная линия | 500 000…60 000 000 | 12, 18, 24, 36 | 12.0…32.0 | ≥ 0 |
| `LEASING` | Лизинг | 500 000…100 000 000 | 12, 24, 36, 48, 60 | 7.2…19.2 | всегда 0 |
| `INVESTMENT` | Инвестиционный кредит | 1 000 000…500 000 000 | 24, 36, 60, 84, 120 | 10.8…28.8 | ≥ 0 |
| `SECURED_RE` | Кредит под залог недвижимости | 1 000 000…150 000 000 | 36, 60, 84, 120 | 10.2…27.2 | > 0, `amount ≤ 0.7 × collateral_value`, вид — `REAL_ESTATE` |
| `GOV_1764` | Льготный кредит (программа 1764) | 500 000…500 000 000; micro до 10 000 000 | 12, 24, 36, 60; micro до 36 | 16.75; micro 17.5 | ≥ 0 |
| `FACTORING` | Факторинг | 1 000 000…500 000 000 | 1, 2, 3, 4, 6 | 14.4…38.4 | всегда 0 |

Ставка 1 знак после запятой. У `GOV_1764` ставка фиксированная по программе. `amount` у
`BUSINESS_CARD` — кредитный лимит, у `OVERDRAFT`, `CREDIT_LINE_REV`, `FACTORING` — лимит, у остальных —
сумма кредита.

| `collateral_type` | `collateral_subtype` |
|---|---|
| `REAL_ESTATE` недвижимость | `APARTMENT` квартира, `HOUSE` жилой дом, `OFFICE` офис, `RETAIL_SPACE` торговое помещение, `WAREHOUSE` склад, `INDUSTRIAL_BUILDING` производственное здание, `LAND` земельный участок |
| `VEHICLES` транспорт | `CAR` легковой автомобиль, `TRUCK` грузовой транспорт, `SPECIAL_MACHINERY` спецтехника |
| `EQUIPMENT` оборудование | `PRODUCTION_EQUIPMENT` производственное, `TRADE_EQUIPMENT` торговое |
| `INVENTORY` товары в обороте | `GOODS` готовые товары, `RAW_MATERIALS` сырьё и материалы |
| `FINANCIAL` финансовые активы | `DEPOSIT` депозит, `BONDS` облигации, `SHARES` акции, `RECEIVABLES` дебиторская задолженность |
